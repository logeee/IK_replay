## 一、YOLO 配置说明

### 1.1 模型文件

| 项 | 值 |
|---|---|
| 路径 | `models/Xuanniu_D.pt`（仓库根目录下） |
| 大小 / MD5 | 20 490 392 字节 / `58fdc9067da1828ffd79b67a165e44f8` |
| 任务类型 | segment（实例分割，面板拟合会用到多边形掩码） |
| 类别 | `0 = 远方就地左`，`1 = 远方就地右` |

新模型**只认开关手柄的物理指向，不读柜面印刷文字**，因此实验室柜、
工厂柜识别结果一致，视觉层不再区分现场。

类别名的唯一权威定义在 **`api/switch_states.py`**（`SCENE_LEFT` /
`SCENE_RIGHT` / `SCENE_CLASSES`），所有服务与流程代码都从这里引用，
不要在别处手写类别字符串。

语义与物理的对应按工厂柜印刷**全局固定**：

- 就地 = 左，远方 = 右；
- `Change the switch from remote to close`（远方→就地）＝ 向左拨（rtl）；
- `Change the switch from close to remote`（就地→远方）＝ 向右拨（ltr）；
- 方向由指令唯一决定，`site` 不再参与方向计算，只决定该柜验证过哪些动作。

### 1.5 以后如何更换模型

1. 传输后**先校验完整性**（本次踩过坑：曾收到全零字节的损坏文件）：

   ```bash
   md5sum 新模型.pt                 # 与源机器比对
   head -c 16 新模型.pt | xxd       # 应以 PK 开头（zip 魔数），不能全是 00
   ```

2. 放入 `models/` 并更新 1.4 节列出的路径（或沿用同名覆盖）。
3. 验证类别与代码一致：

   ```bash
   /home/robot/miniconda3/envs/fastapi/bin/python -c "
   from ultralytics import YOLO
   m = YOLO('models/Xuanniu_D.pt')
   print(m.task, m.names)"
   ```

   若类别名有变，同步修改 `api/switch_states.py` 并全量跑测试。
4. 重启服务（`./prepare.sh`），用 7004 的 `/api/yolo/scene` 实拍确认。

## 二、本次改造内容（旧模型 → Xuanniu_D.pt）

### 2.1 背景与目标

旧模型（`Xuanniu.pt`）按柜面**印刷文字**识别「就地 / 远方」。实验室柜
与工厂柜印刷相反，导致方向计算必须依赖 `site`，同一指令在不同现场对应
相反的物理动作，容易出错。

新模型只认**开关物理指向（左 / 右）**，目标：

- 任何现场识别结果一致，视觉层彻底去掉 site 分叉；
- 物理拨动方向由指令（language）唯一决定；
- 语义↔物理按工厂柜印刷全局固定（就地=左、远方=右），实验室柜也按
  此语义执行与核验。

### 2.2 修改清单

**新增**

- `api/switch_states.py`：物理类别常量（`SCENE_LEFT/SCENE_RIGHT/
  SCENE_CLASSES/SCENE_SHORT`）与 `opposite_scene()` 助手，全仓唯一出处。

**感知层**

- `api/yolo_server.py`：类别改从 `switch_states` 引用；默认模型改
  `Xuanniu_D.pt`；文档字符串同步。
- `adapters/reach/flip_verification.py`：`SCENES`、`_opposite` 改用共享
  常量；错误文案改「开关指向（左/右）」。
- `api/yolo_client.py`：返回值说明更新为新类别名。

**决策层**

- `api/flow.py`：
  - `FLIP_KIND_STATES` 改为物理类别（kind → 拨前/拨后指向）；
  - 新增 `KIND_DIRECTIONS`（kind 唯一决定 ltr/rtl），删除按 site 反转的
    `SITE_RTL_KIND` 逻辑，`resolve_flip_intent` 不再依赖 site 定方向；
  - 新增 `KIND_LABELS`（就地/远方人读标签），供日志与配置文案使用，
    与 YOLO 比对用的物理类别分离。
- `api/dispatch.py`：`_capability_for_kind` 按 `KIND_DIRECTIONS` 查能力；
  预检、文案、来源字符串同步；`SITE_SUPPORTED_KINDS` 更新（实验室柜
  已验证动作改为「远方→就地（向左拨）」，向右拨未验证）。

**目标点**

- `api/cabinet_target_finder.py`：`_DETECTION_RULES` 键改为物理类别。
  ⚠ 偏移值沿用旧模型标定（旧「远方」≈新「远方就地右」的框），
  **待真机复核**。

**前端**

- `web/dispatch.html`：现场下拉、任务下拉标签、`SITE_LANGUAGE_OPTIONS`
  改为方向唯一语义；实验室柜任务方向修正。
- `web-picks`（Stats/Detail/Gallery 三个视图）：徽标与配色**新旧类别
  兼容**（历史记录仍是「就地/远方」）。web-picks 尚未构建过 dist，
  需要看画廊时再 `npm install && npm run build`。

**启动与配置**

- `prepare.sh` / `prepare-pointcloud.sh` / `api/__init__.py`：模型路径与
  启动命令统一为 `Xuanniu_D.pt` + fastapi 环境。
- `config/capability_registry.json`：能力条目方向语义与新映射一致
  （远方→就地 = rtl，实验室柜、工厂柜共用）。

**测试**（94 个全部通过）

- 更新 `test_bidirectional_flow`、`test_wrist_evidence`、
  `test_cabinet_auto_pick`、`test_pointcloud`、`test_capability_dispatch`
  五个文件的类别与方向断言；`test_dispatch_dashboard`、
  `test_yolo_server` 无需改动、复跑通过。

**文档**

- `docs/拨闸API使用说明.md`、`docs/17001拨闸API双向使用说明.md` 升到
  v6：方向只看 language；`/task/status` 的 `flip_from/flip_to` 改为返回
  物理类别名。

**环境**

- fastapi 环境安装 torch/torchvision（CPU）+ ultralytics 8.4.138；
  实测模型加载、类别断言、随机图推理均通过。

### 2.3 对接方需要知道的行为变化

- **实验室柜指令变化**：以前「lab + close_to_remote」= 向左拨；现在
  向左拨请发 `remote_to_close`（方向只看指令，全现场一致）。依赖旧
  规则的脚本需要改。
- `/task/status` 的 `flip_from/flip_to` 从「就地/远方」变为
  「远方就地左/远方就地右」。
- 检查接口第 4 步的 `scene` 字段同样返回新类别名。
