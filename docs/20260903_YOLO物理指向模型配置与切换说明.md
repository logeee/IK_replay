## 一、YOLO 配置说明

### 1.1 模型文件

| 项 | 值 |
|---|---|
| 路径 | `models/Xuanniu_hhy.pt`（仓库根目录下） |
| 大小 / MD5 | 20 500 637 字节 / `b74f00daa0145b8c4c2dfc6e597a46b6` |
| 任务类型 | segment（实例分割，面板拟合会用到多边形掩码） |
| 类别 | `0 = 面板`，`1 = 旋钮左`，`2 = 旋钮右` |

模型**只认开关旋钮的物理指向，不读柜面印刷文字**，因此实验室柜、
工厂柜识别结果一致，视觉层不再区分现场。「面板」类**不参与开关状态
判定**（7004 `/scene` 归类、17001 预检、7005 面板拟合选框都只看旋钮
左/右），只被柜面坐标系构建**方法二**（`api/cabinet_frame/
method2_panel_edges.py`，18000 → 柜面坐标系 → `method2_panel_edges`）
使用：取置信度最高的面板 mask 点云拟合平面（Y 轴）与矩形两边，更接近
画面水平的边为 X 轴，Z = X × Y。没检出面板时方法二直接报错，不回退
方法一。

上一版模型 `Xuanniu_D.pt`（`58fdc9067da1828ffd79b67a165e44f8`，类别
`远方就地左/右`）仍保留在 `models/` 下，语义一一对应：远方就地左 =
旋钮左，远方就地右 = 旋钮右。

类别名的唯一权威定义在 **`api/switch_states.py`**（`SCENE_LEFT` /
`SCENE_RIGHT` / `SCENE_CLASSES`），所有服务与流程代码都从这里引用，
不要在别处手写类别字符串。

语义与物理的对应按工厂柜印刷**全局固定**：

- 就地 = 左，远方 = 右；
- `Change the switch from remote to close`（远方→就地）＝ 向左拨（rtl）；
- `Change the switch from close to remote`（就地→远方）＝ 向右拨（ltr）；
- 方向由指令唯一决定，`site` 不再参与方向计算，只决定该柜验证过哪些动作。

### 1.5 以后如何更换模型

1. 传输后**先校验完整性**（本次踩过坑：曾收到全零字节的损坏文件）：

   ```bash
   md5sum 新模型.pt                 # 与源机器比对
   head -c 16 新模型.pt | xxd       # 应以 PK 开头（zip 魔数），不能全是 00
   ```

2. 放入 `models/` 并更新 1.4 节列出的路径（或沿用同名覆盖）。
3. 验证类别与代码一致：

   ```bash
   /home/robot/miniconda3/envs/fastapi/bin/python -c "
   from ultralytics import YOLO
   m = YOLO('models/Xuanniu_hhy.pt')
   print(m.task, m.names)"
   ```

   若类别名有变，同步修改 `api/switch_states.py` 并全量跑测试。
4. 重启服务（`./prepare.sh`），用 7004 的 `/api/yolo/scene` 实拍确认。

## 二、2026-09-03 改造记录（Xuanniu.pt → Xuanniu_D.pt）

### 2.1 背景与目标

旧模型（`Xuanniu.pt`）按柜面**印刷文字**识别「就地 / 远方」。实验室柜
与工厂柜印刷相反，导致方向计算必须依赖 `site`，同一指令在不同现场对应
相反的物理动作，容易出错。

新模型只认**开关物理指向（左 / 右）**，目标：

- 任何现场识别结果一致，视觉层彻底去掉 site 分叉；
- 物理拨动方向由指令（language）唯一决定；
- 语义↔物理按工厂柜印刷全局固定（就地=左、远方=右），实验室柜也按
  此语义执行与核验。

### 2.2 修改清单

**新增**

- `api/switch_states.py`：物理类别常量（`SCENE_LEFT/SCENE_RIGHT/
  SCENE_CLASSES/SCENE_SHORT`）与 `opposite_scene()` 助手，全仓唯一出处。

**感知层**

- `api/yolo_server.py`：类别改从 `switch_states` 引用；默认模型改
  `Xuanniu_D.pt`；文档字符串同步。
- `adapters/reach/flip_verification.py`：`SCENES`、`_opposite` 改用共享
  常量；错误文案改「开关指向（左/右）」。
- `api/yolo_client.py`：返回值说明更新为新类别名。

**决策层**

- `api/flow.py`：
  - `FLIP_KIND_STATES` 改为物理类别（kind → 拨前/拨后指向）；
  - 新增 `KIND_DIRECTIONS`（kind 唯一决定 ltr/rtl），删除按 site 反转的
    `SITE_RTL_KIND` 逻辑，`resolve_flip_intent` 不再依赖 site 定方向；
  - 新增 `KIND_LABELS`（就地/远方人读标签），供日志与配置文案使用，
    与 YOLO 比对用的物理类别分离。
- `api/dispatch.py`：`_capability_for_kind` 按 `KIND_DIRECTIONS` 查能力；
  预检、文案、来源字符串同步；`SITE_SUPPORTED_KINDS` 更新（实验室柜
  已验证动作改为「远方→就地（向左拨）」，向右拨未验证）。

**目标点**

- `api/cabinet_target_finder.py`：`_DETECTION_RULES` 键改为物理类别。
  ⚠ 偏移值沿用旧模型标定（旧「远方」≈新「远方就地右」的框），
  **待真机复核**。

**前端**

- `web/dispatch.html`：现场下拉、任务下拉标签、`SITE_LANGUAGE_OPTIONS`
  改为方向唯一语义；实验室柜任务方向修正。
- `web-picks`（Stats/Detail/Gallery 三个视图）：徽标与配色**新旧类别
  兼容**（历史记录仍是「就地/远方」）。web-picks 尚未构建过 dist，
  需要看画廊时再 `npm install && npm run build`。

**启动与配置**

- `prepare.sh` / `prepare-pointcloud.sh` / `api/__init__.py`：模型路径与
  启动命令统一为 `Xuanniu_D.pt` + fastapi 环境。
- `config/capability_registry.json`：能力条目方向语义与新映射一致
  （远方→就地 = rtl，实验室柜、工厂柜共用）。

**测试**（94 个全部通过）

- 更新 `test_bidirectional_flow`、`test_wrist_evidence`、
  `test_cabinet_auto_pick`、`test_pointcloud`、`test_capability_dispatch`
  五个文件的类别与方向断言；`test_dispatch_dashboard`、
  `test_yolo_server` 无需改动、复跑通过。

**文档**

- `docs/拨闸API使用说明.md`、`docs/17001拨闸API双向使用说明.md` 升到
  v6：方向只看 language；`/task/status` 的 `flip_from/flip_to` 改为返回
  物理类别名。

**环境**

- fastapi 环境安装 torch/torchvision（CPU）+ ultralytics 8.4.138；
  实测模型加载、类别断言、随机图推理均通过。

### 2.3 对接方需要知道的行为变化

- **实验室柜指令变化**：以前「lab + close_to_remote」= 向左拨；现在
  向左拨请发 `remote_to_close`（方向只看指令，全现场一致）。依赖旧
  规则的脚本需要改。
- `/task/status` 的 `flip_from/flip_to` 从「就地/远方」变为
  「远方就地左/远方就地右」。
- 检查接口第 4 步的 `scene` 字段同样返回新类别名。

### 2.4 遗留与真机验证清单

1. **取点偏移复核**：`cabinet_target_finder` 的偏移及 `api/flow.py`
   中 `POINT_AU` 像素兜底均按旧模型的框标定；若新模型框范围不同，
   取点会偏，首次真机先站位检查 + 低速验证。
2. 实验室柜「就地→远方（向右拨）」仍未真机开放（能力注册表中无该
   现场条目）。
3. `test_capability_registry` 现有 5 个失败属于并行进行中的「起手式
   认领 capability_id 改造」，与本次无关。

## 三、2026-09-06 改造记录（Xuanniu_D.pt → Xuanniu_hhy.pt）

### 3.1 模型差异

| | Xuanniu_D.pt | Xuanniu_hhy.pt |
|---|---|---|
| 类别 | `0 远方就地左`，`1 远方就地右` | `0 面板`，`1 旋钮左`，`2 旋钮右` |
| 语义 | — | 旋钮左 ≡ 远方就地左（就地），旋钮右 ≡ 远方就地右（远方） |

本次**只接旋钮类**，「面板」类各链路一律忽略，留给柜面坐标系方法二。

### 3.2 修改清单

- `api/switch_states.py`：`SCENE_LEFT/RIGHT` 改为 `旋钮左/旋钮右`；新增
  `LEGACY_SCENE_NAMES`（旧名 → 新名，仅供读历史记录）。
- `api/cabinet_panel_fit.analyze_yolo_mask_panel`：选框只在 `SCENE_CLASSES`
  里取置信度最高的；帧里只有面板类时返回 `available=False`，reason 写明
  「没有旋钮类实例」。之前是全类别取最高置信度，新模型下会选中「面板」
  导致 `predict_target` 报不支持类别。
- 模型路径默认值：`prepare.sh`、`prepare-pointcloud.sh`、`api/yolo_server.py`、
  `api/pointcloud_viewer.py`、`api/yolo_collect.py`、`api/__init__.py`。
- 文档字符串同步：`yolo_server` / `yolo_client` / `flow` / `dispatch` /
  `flip_verification` / `cabinet_target_finder`。
- `web-picks` 三个视图：`旋钮右/旋钮左` 加入配色与「远方/就地」徽标判定，
  旧类别名保留兼容。
- 测试：新增 `test_panel_analysis_ignores_non_knob_classes`；全量 350 个通过。

### 3.3 真机验证清单（换模型后首次上机）

1. **旋钮 mask 的拟合矩形中心是否与旧模型一致**：`cabinet_target_finder`
   的墙面系偏移（±47.9 / +5.9 / −19.5 mm）是相对拟合矩形中心标定的。若
   `旋钮左/右` 的 mask 只覆盖旋钮本体而非旧模型的整块区域，矩形中心会
   变，偏移需重标。先用 `data/panel_fit_debug/` 叠加图目视核对，再用
   7005 手动模式确认落点后放开自动。
2. `config/dispatch_defaults.json` 里的偏移 preset 同样是旧模型下标定的，
   随上一条一起复核。
3. `api/flow.py` 像素兜底路径（`POINT_AU/POINT_AV`，仅无 7005 时使用）
   的几何按最早的整框标定，新模型的旋钮小框下已不成立，启用前必须重标。
4. 7004 启动日志应打出类别 `{0: '面板', 1: '旋钮左', 2: '旋钮右'}` 且
   没有「模型没有场景类别」警告；`/api/yolo/scene` 实拍应返回 `旋钮左/右`。
