# 17001 开关双向拨动作业 API 使用说明

> 版本：v6（2026-09-03，视觉切换为物理指向识别 Xuanniu_D.pt）  
> 适用对象：作业平台、导航平台及现场联调人员

## 1. 最重要的方向说明

`language` **唯一决定物理拨动方向**，任何现场一致（v6 起）：

- `Change the switch from close to remote`：就地 → 远方 = **从左到右（向右拨）**
- `Change the switch from remote to close`：远方 → 就地 = **从右到左（向左拨）**

视觉识别使用物理指向模型（类别：`远方就地左` / `远方就地右`，不读
印刷文字），语义与物理的对应按工厂柜印刷全局固定：就地=左、远方=右。
`site` 不再参与方向计算，只决定该柜验证过哪些动作。

### 1.1 工厂柜（factory）

| 物理方向 | 状态变化 | language | 支持情况 |
|---|---|---|---|
| **从左到右（向右拨）** | 就地 → 远方 | `Change the switch from close to remote` | ✅ |
| **从右到左（向左拨）** | 远方 → 就地 | `Change the switch from remote to close` | ✅ |

### 1.2 实验室柜（lab）

| 物理方向 | 状态变化 | language | 支持情况 |
|---|---|---|---|
| **从右到左（向左拨）** | 远方 → 就地 | `Change the switch from remote to close` | ✅ |
| **从左到右（向右拨）** | 就地 → 远方 | `Change the switch from close to remote` | ❌ 尚未真机开放 |

注意：实验室柜印刷与工厂柜相反，但 v6 起机器人不读印刷、统一按工厂
语义执行与核验，因此实验室柜上任务的 language 应按**物理动作**选择
（要向左拨就发 `remote_to_close`），不要按柜上印刷文字选择。

### 1.3 关于旧调用（v5 及更早）

v5 及更早版本中物理方向 = `site + language` 联合决定（实验室柜
`close_to_remote` 曾对应从右到左）。v6 起该规则废止：方向只看
language。历史脚本若依赖"lab + close_to_remote = 向左拨"，需改为
`remote_to_close`。

API 当前没有供调用方直接设置的 `direction` 请求字段。`direction` 由
`language` 唯一计算，并在 `/task/status` 中以 `ltr` 或 `rtl`
返回，供调用方核对。

## 2. 服务地址

```text
http://<机器人IP>:17001
```

下面示例使用：

```text
http://192.168.61.142:17001
```

## 3. 推荐调用流程

```text
导航到位
  → POST /check/flip
  → passed=true 且 need_flip=true
  → POST /task/flip
  → 每 1～2 秒 GET /task/status
  → state=done 后检查 result.ok
```

站位检查不是强制接口，但生产作业建议始终调用。

## 4. 从左到右（工厂柜）

### 4.1 站位检查

```bash
curl -X POST 'http://192.168.61.142:17001/check/flip' \
  --max-time 300 \
  -H 'Content-Type: application/json' \
  -d '{
    "site": "factory",
    "language": "Change the switch from close to remote"
  }'
```

含义：

- 现场：工厂柜
- 当前预期状态：就地
- 目标状态：远方
- 物理方向：从左到右（向右拨）

### 4.2 触发任务

```bash
curl -X POST 'http://192.168.61.142:17001/task/flip' \
  -H 'Content-Type: application/json' \
  -d '{
    "site": "factory",
    "language": "Change the switch from close to remote",
    "retries": 3
  }'
```

## 6. `POST /check/flip`

站位检查是同步接口，可能启动相机或让机器人原地转身纠正朝向。HTTP 客户端
超时应设置为至少 300 秒。

请求字段：

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `language` | 是 | string | 固定状态变化指令 |
| `site` | 建议必传 | string | `factory` 或 `lab`；不传则读取机器人默认配置 |

典型返回：

```json
{
  "ok": true,
  "passed": true,
  "need_flip": true,
  "failed_step": null,
  "message": "站位合格，可以调用 /task/flip（相机保持开启供其复用）",
  "camera_kept": true,
  "duration_s": 16.2,
  "steps": []
}
```

调用方必须处理三个分支：

1. `passed=true, need_flip=true`：立即调用 `/task/flip`。
2. `passed=true, need_flip=false`：开关已经是目标状态，作业成功结束，不要再拨。
3. `passed=false`：站位不合格，根据 `failed_step` 和 `message` 调整机器人。

异常：

- HTTP 422：`language`、`site` 或现场/任务组合不合法；
- HTTP 409：已有站位检查或拨闸任务正在执行。

## 7. `POST /task/flip`

该接口异步启动任务，不等待拨动完成。

请求字段：

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `language` | 是 | string | 固定状态变化指令 |
| `site` | 建议必传 | string | `factory` 或 `lab` |
| `retries` | 否 | int | 最大尝试轮数，范围 1～20，默认 3 |
| `target_offset_wall_mm` | 否 | object | 本次目标点微调；普通作业不要传 |

成功接收：

```json
{
  "ok": true,
  "task_id": "78dfd3c094"
}
```

这里的 `ok=true` 只表示任务已接收，不表示拨动成功。最终结果必须通过
`GET /task/status` 获取。

异常：

- HTTP 422：请求参数不合法；
- HTTP 409：已有任务或站位检查正在执行。

## 8. `GET /task/status`

```bash
curl 'http://192.168.61.142:17001/task/status'
```

建议每 1～2 秒轮询一次。

运行中的方向信息示例：

```json
{
  "ok": true,
  "state": "running",
  "task_id": "78dfd3c094",
  "site": "factory",
  "kind": "close_to_remote",
  "direction": "ltr",
  "flip_from": "远方就地左",
  "flip_to": "远方就地右",
  "result": null
}
```

方向字段：

- `direction=ltr`：从左到右；
- `direction=rtl`：从右到左。

`flip_from` / `flip_to` 为视觉核验用的开关物理指向类别
（`远方就地左` / `远方就地右`），v5 及更早版本此处为印刷语义
（`就地` / `远方`）。

任务结束时 `state=done`：

```json
{
  "state": "done",
  "result": {
    "ok": true,
    "code": 0,
    "code_name": "OK",
    "message": "拨动成功",
    "detail": {}
  }
}
```

判断原则：

- `state=done` 且 `result.ok=true`：作业成功；
- `state=done` 且 `result.ok=false`：作业失败，按 `result.code` 处理；
- 不要解析 `log` 判断成功，`log` 只供人查看。

## 9. 中止任务

紧急停止并释放手臂：

```bash
curl -X POST 'http://192.168.61.142:17001/emergency/stop'
```

兼容接口：

```bash
curl -X POST 'http://192.168.61.142:17001/task/abort'
```

强制停止后，机械臂可能停在柜前并已释放控制权，不会自动收回。必须人工确认
机械臂姿态后再执行其他运动。

## 10. Python 对接示例

下面通过物理方向选择工厂柜请求。

```python
import time
import requests

BASE = "http://192.168.61.142:17001"

FACTORY_COMMANDS = {
    "left_to_right": "Change the switch from close to remote",
    "right_to_left": "Change the switch from remote to close",
}


def flip_factory(direction: str) -> dict:
    try:
        language = FACTORY_COMMANDS[direction]
    except KeyError:
        raise ValueError("direction 只能是 left_to_right 或 right_to_left")

    body = {
        "site": "factory",
        "language": language,
        "retries": 3,
    }

    # 1. 站位检查
    response = requests.post(f"{BASE}/check/flip", json=body, timeout=300)
    response.raise_for_status()
    check = response.json()

    if not check["passed"]:
        raise RuntimeError(
            f"站位不合格（步骤 {check.get('failed_step')}）：{check['message']}"
        )
    if not check["need_flip"]:
        return {"ok": True, "message": "开关已经是目标状态，无需拨动"}

    # 2. 异步启动任务
    response = requests.post(f"{BASE}/task/flip", json=body, timeout=5)
    response.raise_for_status()
    accepted = response.json()

    # 3. 轮询最终结果
    while True:
        response = requests.get(f"{BASE}/task/status", timeout=5)
        response.raise_for_status()
        status = response.json()

        if status["state"] == "done":
            return status["result"]

        time.sleep(2)


# 工厂柜：从左到右
result = flip_factory("left_to_right")

# 工厂柜：从右到左
# result = flip_factory("right_to_left")

if not result["ok"]:
    raise RuntimeError(
        f"拨动失败 [{result['code']} {result['code_name']}] "
        f"{result['message']}"
    )
```

## 11. 作业前提

- 机器人正对目标柜体；
- 距柜面至少 0.44 m，建议不超过 0.8 m；
- 手臂空闲、周围无人且无遮挡；
- 同一时刻只能执行一个站位检查或拨闸任务；
- 工厂柜双向动作所需的起手式和标定配置已经部署；
- `/check/flip` 可能让机器人原地转身，应按真实运动任务进行安全管控。
