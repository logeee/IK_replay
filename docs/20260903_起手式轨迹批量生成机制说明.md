# 起手式轨迹批量生成机制说明

> 整理日期：2026-09-03
> 结论：`data/sequences/` 里 39 条轨迹只有 2 条是手工录制的，其余 **37 条全部由
> `_retarget_sequence()` 从一条起手动作批量生成**。本文记录该机制的位置、原理、
> 谱系与复用方法。

## 1. 核心引擎：`_retarget_sequence()`

- 位置：`api/gravity_calibration.py`（约第 413 行）
- 对外接口：18002 重力标定服务的 `POST /api/gravity/sequences/retarget`
- 引入提交：`fa29ec9 加入了不同距离起手式的学习方法`

函数签名：

```python
def _retarget_sequence(
    source_filename: str,        # 源轨迹文件名（data/sequences/ 下）
    target_name: str,            # 新轨迹名，必须以距离开头，如 "0.57-起手式新"
    forward_offset_m: float,     # 前向偏移（根坐标系 +X），米
    *,
    offset_root_m: list[float] | None = None,  # 可选：根坐标系 XYZ 任意偏移向量
    endpoint_name: str | None = None,          # 可选：终点路点名（默认 "X.XX终点"）
    output_timestamp: str | None = None,       # 可选：固定输出文件时间戳（批量时统一）
) -> dict:
    """Retarget one recorded motion style over its full TCP arc length."""
```

### 工作流程（保留动作风格、只挪终点）

1. **输入校验**：新名字必须以距离开头（如 `0.57`）；偏移向量长度限制在
   0.01mm–200mm（超过 0.20m 直接拒绝）。
2. **正运动学还原轨迹**：把源轨迹每帧关节角用机器人模型（`app.robots` +
   源轨迹自带的 `tcp_offset` 工作点）算出 TCP 位姿序列，按 TCP 弧长归一化进度。
3. **五次平滑步偏移**：用 quintic smoothstep（6t⁵ − 15t⁴ + 10t³）沿弧长进度
   渐进施加偏移——**起手点完全不动，越接近终点偏移越满**。因此生成的轨迹保持
   原动作的"起手风格"，只是终点挪到了新距离。
4. **逐帧重解 IK**：以上一帧解为种子保证关节连续性；先按 2mm / 2° 严格解，
   失败则退化为"位置优先"（姿态容差放宽到 8°，rotation_weight=0.05），
   并把该帧记入 `position_priority_frames`。任何一帧仍失败则整条报错。
5. **安全检查**：加密帧到关节步长 ≤ 0.04 rad（`_densify_joint_frames`），
   逐帧做模型自碰撞检测，任何一帧碰撞就整条报错、**不落盘**。
6. **原子落盘两个文件**：
   - 终点路点 → `data/waypoints/<终点名>_<时间戳>.json`
   - 新序列 → `data/sequences/<新名字>_<时间戳>.json`

   序列 JSON 的 `trajectory.retarget` 元数据记录完整谱系：`source_sequence`、
   `offset_root_m`、`axis_root`、`position_priority_frames` 等。执行时长按
   最大关节行程 / 0.35 rad·s⁻¹ 估算（下限 1s）。

## 3. 配套批量脚本：`tools/lower_left_trajectories.py`

仓库里留存的唯一批量驱动脚本，演示了标准的批量调用方式：

1. 按正则 `^X.XX-左-起手式_时间戳.json$` 扫描全部左臂起手式轨迹及其终点路点；
2. 整体备份到 `data/backups/left_tcp_before_down_<时间戳>/`（含 manifest.json）；
3. 循环调用 `_retarget_sequence(..., offset_root_m=[0,0,-down_m],
   output_timestamp=原时间戳)`，让每条终点 TCP 沿根坐标系 -Z 平滑下降
   （默认 0.10m，上限 0.20m），保留原文件名原地覆盖；
4. 任何一条失败自动回滚全部原文件。

用法：

```bash
cd /home/robot/yx/project/IK_replay
# 默认 dry-run，只列出待处理文件
python3 tools/lower_left_trajectories.py --down-m 0.10
# 确认后真正写入
python3 tools/lower_left_trajectories.py --down-m 0.10 --apply
```

## 4. 如何再批量生成新距离

两条路都通：

**方式 A：HTTP 接口**（需先启动 18002 重力标定服务）

```bash
curl -X POST http://127.0.0.1:18002/api/gravity/sequences/retarget \
  -H 'Content-Type: application/json' \
  -d '{"source_file": "0.46-起手式新_20260822_031411.json",
       "target_name": "0.61-起手式新",
       "forward_offset_m": 0.15}'
```

**方式 B：直接 import 写循环**（仿照 `lower_left_trajectories.py`）

```python
import sys
sys.path.insert(0, "/home/robot/yx/project/IK_replay")
from api.gravity_calibration import _retarget_sequence

SOURCE = "0.46-起手式新_20260822_031411.json"
for target in [0.61, 0.62, 0.63]:
    result = _retarget_sequence(
        SOURCE,
        f"{target:.2f}-起手式新",
        round(target - 0.46, 4),          # 前向偏移 = 目标距离 - 源距离
        # output_timestamp="20260903_000000",  # 可选：批量统一时间戳
    )
    print(result["sequence_file"], result["minimum_model_clearance_mm"])
```

注意事项：

- 单次偏移上限 0.20m；更远距离请分级接力（以上一批生成结果为新源）。
- 生成过程逐帧 IK + 碰撞检测，任何失败都不会写文件，可放心批量跑。
- 生成后新序列自动进入 `data/sequences/`，会被 18000 能力总管的
  起手式池子与 18002 离线回放列表识别。
