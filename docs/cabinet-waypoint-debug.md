# 柜面 A/B 点位调试

18001 单臂页面、双臂工作台的每个手臂窗口均有「调试方式」按钮。
在页面内弹窗选择「经典模式」或「A/B 点位调试」，选择两个带 RGBD 的点位，保存为默认。
默认值按本浏览器、机器人、手臂分别保存；初次使用仍为经典模式。

经典模式默认启用「分段模式」：主段到位后弹窗选择**向左 / 向右**，不会自动横移。
切换并保存经典模式时也会恢复此开关；开关跨刷新保存，手动取消后仍可使用原自动流程。
没有保存过该开关的旧设置按「到点后手动选择」迁移。
主页面的「左右操作」可随时重新打开方向窗口；仅打开/关闭不会运动。
手动按钮固定左、右方向，距离取输入值的绝对值；原自动流程继续按带符号距离选择方向。

- A 对应旋钮左的记录，B 对应旋钮右的记录。左臂建议值为 `L-HHY-L-D-V4` / `L-HHY-R-D-V1`，仅建议与当前 TCP 匹配的记录；没有可用 V4 时仍可建议兼容的左侧 V1。
  按本次更新要求，H2 左臂刷新页面并读取到兼容的 `L-HHY-L-D-V4_20260917_170714.json` 后，
  将已保存的 A 切换为该 V4 一次。后续手动选择优先，刷新不再覆盖；B、偏移和助力参数保持原值。
- 第一段保持已有的选点、规划、执行方式。A/B 模式到位后一定暂停，不自动横移或收回。
- 弹窗提供 **直接到 A、直接到 B**，以及 **A→B、B→A、到结束点位、关闭**。
  可随时从主页面的「A/B 操作」打开，不要求先执行选点主轨迹。
- **直接到 A / B**：从实测当前位置去指定记录位姿，使用各自独立的 XYZ 偏移，默认全为 0，助力固定为 0。
  在操作窗口「直接到点」旁点击「偏移与容差…」，A/B 分卡片填写，每轴偏移 −100～+100 mm，
  位置容差 0.1～100 mm（默认 10），朝向容差 0.1～45°（默认 2）。设置按浏览器、机器人和手臂保存。
  位置容差是 TCP 到偏移后目标的三维总距离，朝向容差是两个姿态的总旋转夹角，两项同时满足才算到位。
  规划前已满足这两项时不发起运动；否则仍规划到目标位姿，轨迹结束后按同样容差验收，不在中途提前截断轨迹。
  IK 求解验收、执行前终点检查和实际到位验收统一使用所设容差，均相对原目标（含偏移）计算。
  求解器仍尽量减小目标误差，不因放宽容差而提前停止优化。容差不补偿视觉定位和标定误差。
  不修改已保存的往返偏移、助力或时间；A→B / B→A 保留原判定。未接管时仅预演，接管后再次点击会重新定位规划。
  去 A 不要求靠近 B，去 B 不要求靠近 A；仍需柜面可定位、目标位姿可达、关节不越限，
  并保留执行互斥、规划有效期、实测起点一致性和已启用的碰撞检查。
- **A→B 从实测当前位置直接去 B**；B→A 直接去 A，不先返回另一个记录点。
- 两个方向各有独立的「柜面 X / Y / Z 偏移」，单位 mm，每轴默认 0，范围 −100～+100。
  X 正向右、Y 正向柜内、Z 正向上，负值反向；B→A 的偏移作用于 A，A→B 作用于 B。
  例如 B→A 的 X 填 −10 表示到 A 的记录位置再向柜面左侧偏移 10 mm。
  旧版已保存的 X 偏移保留，新增 Y/Z 默认为 0。
  只改变终点位置，不改变记录朝向、TCP 安装偏移或原始点位文件；每次相对原记录计算，不累计。
- 设置弹窗按 A/B 分卡片：点位选择独占一行，下方排列三轴偏移和助力；窄屏助力单独换行。
  标题与保存栏固定，内容区可滚动。
  往返操作按钮和规划结果显示实际配置偏移。
- 两向独立设置「助力」（0～40 N，默认 0 关闭）：**A→B 为柜面 +X，B→A 为柜面 −X**。
  这是 TCP 处的固定柜面方向前馈力，不自动识别旋钮转轴或切向，不修改 A/B 目标位姿。
  位置偏移与助力独立；原来仅为增加出力而设置的偏移，可自行改回 0。
- 两向共用建立时间（0.1～5 s，默认 0.5）、段末保持（0～5 s，默认 0）、撤力时间
  （0.1～5 s，默认 0.65）。按实际经过时间用平滑曲线建立助力，随后维持；短轨迹
  尚未建立满力时，从当前力度撤除，不跳变到满力。急停、卸力、控制权丢失立即清零。
- 每次规划绑定本次面板 X 轴及助力参数。执行中按当前实测关节角更新位置雅可比，
  `tau_assist = J_position(q_measured).T @ F_root`；PINK 同时更新世界到根系的方向变换。
  原方案、50Hz 时间轨迹和 PINK 均支持；不会因为助力自动提高运动速度。
  保留原控制器的关节力矩限幅和重力补偿；N 为前馈设定值，不是传感器测得的接触力。
- 助力保持和撤除期间保留真实终点目标，撤力后仍验收位置（10 mm）和朝向（2°）。
  未到位报告失败，不套用旧横移「推力结束即完成」的判断，也不追加强制落点修正。
- 两个方向每次重新采集 RGBD 和机械臂位姿、定位面板、换算目标 XYZ + 朝向。中间朝向自由。
- 到结束点位沿用已有的关节路点收回方式。关闭只关闭窗口。
- 未接管时方向按钮仅生成预演。接管后再次点击会重新定位规划，不执行旧预演。

## 坐标与条件

「朝向模式」也可选择 **目标点使用 A 点柜面朝向 / 目标点使用 B 点柜面朝向**。
下方显示对应 RGBD 点位，可直接更换；与「调试方式」中的 A/B 点位共用同一份选择，
按浏览器、机器人、手臂保存。选择朝向本身不会切换经典/A/B 调试方式或触发运动。

自行更新点位：打开「调试方式」→「A/B 点位调试」，更换 A/B 下拉框后「保存为默认」。
两点均须与当前 TCP 匹配。如果只更新 A 而旧 B 暂不匹配，可在「朝向模式」选择
「目标点使用 A 点柜面朝向」，从「A 点来源」选择新记录，即自动保存 A；随后可切回原朝向模式。
录制了新版本后，重新打开设置或点击来源旁「刷新」即可读取，不需要改代码。

此模式只取点位的**柜面相对旋转**，目标 XYZ 仍使用本次 7005 确认点：

```
R_panel_from_tcp_recorded = R_base_from_panel_recorded.T @ R_base_from_tcp_recorded
R_root_from_tcp_goal     = R_root_from_panel_current @ R_panel_from_tcp_recorded
```

机器人站位变化时重新按当前柜面换算，不复用录制时的基坐标系朝向。
只在终点约束朝向，中途允许转动；不附加 A/B 往返的位置偏移或助力。
RGBD 缺失、TCP/手臂/安装不匹配、柜面坐标轴不完整均拒绝；记录变化或停止/释放后，
旧轨迹不可继续执行。原有独立「已记录朝向」仍保留。

录制数据的相机标定和 TCP 位姿用于求出 `T_panel_from_tcp`。
面板坐标轴来自方法二的矩形边，原点使用**同一块物理面板的矩形中心**。
7005 现有 `origin_camera_m` 是相机到面板的投影，会随站位变化，不能作为固定原点。
此功能不修改 7005 的选点或旧坐标原点。

当前 RGBD 定位提供 `T_camera_from_panel`，经当前相机标定变换到 IK 使用的零腰模型根坐标系：

```
T_root0_from_tcp_goal = T_root0_from_base
                     × T_base_from_camera_now
                     × T_camera_from_panel_now
                     × Translate(cabinet_x_offset_mm / 1000,
                                 cabinet_y_offset_mm / 1000,
                                 cabinet_z_offset_mm / 1000)
                     × T_panel_from_tcp_recorded
```

要求同一面板清晰可见、TCP/机器人/手臂/手部安装匹配、RGBD 与位姿在静止时配对采集。
定位不依赖旋钮类别，旋钮被手遮挡时仍可使用可见面板。尺寸变化超过 15% 拒绝规划；
尺寸检查不能区分两块外观相同的面板，操作者仍须对准原面板。
机身换位置后可以重新定位，原方案执行期间机身应保持静止。
实际精度受深度、面板拟合、手眼标定和控制跟踪误差共同影响，IK 数值误差不是实机精度。

原方案、50Hz 时间轨迹、PINK 都可使用。PINK 需要先锚定，使用本次 RGBD 位姿采样时的世界参考；
原方案不需要锚定。仍遵守双臂串行执行限制。

## 接口与校验

- `GET /api/arms/{arm}/reach/cabinet_waypoints`：当前侧 RGBD 点位与兼容性。
- `POST /api/arms/{arm}/reach/plan_cabinet_waypoint`：`file`、`motion_backend`、`check_collision`、
  `cabinet_x_offset_mm` / `cabinet_y_offset_mm` / `cabinet_z_offset_mm`（数字，各自默认 0），只采集与规划。
  响应和规划凭据确认各轴偏移；前端请求非零偏移却未收到对应确认时拒绝执行，避免旧服务忽略 Y/Z。
- 原 `/execute` 携带服务端返回的 `orientation_plan_id` 和完整轨迹才能执行。
- 直接到点的规划与执行携带相同的 `arrival_tolerance: {"position_mm":10,"orientation_deg":2}`，
  服务端绑定到本次规划凭据，拒绝执行时丢失或改变容差。前端确认服务端回传的容差后才允许执行，
  旧服务未确认时提示更新 18001。未传此字段的往返和原朝向功能沿用已有判定。
- `POST /api/arms/{arm}/reach/plan_orientation` 可使用
  `reference_kind: "cabinet_waypoint_orientation"`、`reference_id: "点位.json"`
  作为朝向来源，其他目标参数沿用 7005 选点；响应确认来源类型和文件。
- 规划和执行都携带相同的 `cabinet_assist`：
  `{"direction":"a_to_b","force_n":6,"ramp_s":0.5,"hold_s":0,"release_s":0.65}`。
  反向使用 `b_to_a`；力度总是非负。参数缺失、非数、越界、执行与规划不一致，
  或与旧 `push` 混用会拒绝。前端收到未确认助力的旧服务响应时不会发起执行。

凭据绑定路径、原始记录摘要、配置、选点版本、世界锚点与停止/释放版本，90 秒过期。
急停或释放会使正在生成的凭据失效。已在目标容差内时返回 `already_at_target`，不发起运动。
碰撞检查沿用页面选项，失败不会退回录制关节角或旧横移流程。

离线测试：`tests/test_cabinet_waypoints.py`；浏览器模拟测试：`tests/browser/cabinet_waypoints.py`。
助力测试：`tests/test_cabinet_assist.py`，覆盖方向、时间曲线、实测姿态变换、停止清零和终点失败。
点位朝向测试：`tests/test_waypoint_orientation.py`；对应浏览器测试 `tests/browser/cabinet_orientation.py`。
浏览器测试拦截所有硬件写入，不会接管或移动真机。
