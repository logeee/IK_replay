# 双臂工作台（第一版）

配置入口：`http://机器人IP:18000/`，顶部左右两张激活组合卡分别保存各侧激活状态、型号、安装方案和补偿。
默认入口 `http://机器人IP:18001/` 保留原单臂界面。
双臂工作台单独从 `18001/arms` 进入；`17001/arms` 也跳转到这里。
右上角保留机器人模型选择，默认显示执行服务使用的机器人（当前为 H2）；切换模型只改变三维预览，不改变执行服务的机器人配置。
左下为机器人左臂，右下为机器人右臂。每侧可以单独启用、接管、选点、规划和卸力。
双侧期望配置统一保存在 `config/reach_arms.json`，由 18000 独占读写；18001 从 18000 快照加载配置，只维护和上报运行状态。原注册表的 `active` 仍作为旧任务分发及单侧服务的兼容默认侧。
18001 在线且双臂已释放时，保存后会要求执行窗口从 18000 重新加载对应侧；18001 离线时配置仍可正常查看、修改和保存，并在执行服务下次启动时自动加载。
每侧未修改时显示“已激活（未改动）”，修改后可“保存更改”。独立的“取消激活”按钮只停用当前侧，保留其已保存配置；停用后可点“激活本侧”恢复。允许仅激活左侧、仅激活右侧或同时激活。
默认沿用启动时的单侧组合；另一侧由操作员选择实物型号和对应补偿文件。

- 单侧“卸力摆位 / 恢复保持”保持原定义：Kp=0、原 hand_move_kd 阻尼、按该侧 grav_in_float 决定重力补偿；恢复时抓取该侧实测角度。
- 顶部可同时卸力、同时恢复保持、停止双臂轨迹、释放双臂。
- 双臂共用一个 arm_sdk 发送器和控制权重。自动轨迹串行，另一侧保持；有任一受控侧卸力时拒绝自动执行。
- 同时启用并不自动接管或发运动指令。单侧接管时，底层仍需保持另一臂，这是原 arm_sdk 控制行为。
- 两侧都已接管时，单侧“释放”被拒绝；请用顶部“释放双臂”交还共用控制权。单侧仍可独立保持或卸力。
- 7005 使用 `?arm=left_arm` / `?arm=right_arm`，快照和浏览器恢复状态分别保存，确认请求核对侧别。
- 7005“选中点”提供旋钮当前类别：默认自动识别，也可手动选择“旋钮右 → 点 1”或“旋钮左 → 点 3”。面板锚点模型下，即使旋钮被遮挡，也可用当前面板几何找点；面板缺失、出画或尺寸异常仍会报错。切换类别会清除页面旧选点，需要重新找点及确认，结果和记录标注手动来源。重新拍摄默认恢复自动识别。
- 无标定的一侧仍可接管、卸力和录制关节位点；视觉选点、TCP 和笛卡尔规划需该侧有效标定。
- 两侧目前共用启动相机及 PINK 世界锚点。重新锚定后应重新取点。
- 规划及执行前检查另一侧当前姿态的简化碰撞体；这不是完整灵巧手网格的连续碰撞验证。

## 目标点使用记录朝向

18001 的“朝向模式 → 目标点使用记录朝向”仅给目标 XYZ 增加一个目标朝向。
默认“不指定朝向（仅 XYZ）”保持原有功能。记录来自 `data/orientation_references/<记录目录>/reference.json`，按机器人、左右侧、手型号和安装标定筛选。
左臂已录入 `L-柜面末端朝向-20260917-024547`；当前 TCP 只有腕系位置偏移，TCP 轴与腕末端轴相同。

从 7005 取点后，以本次柜面坐标系换算记录朝向，解算目标位置和朝向对应的终点关节角。
第一帧保持实际起始关节角，不要求起点接近记录朝向，中途朝向自由变化。
右侧规划使用原有五次关节插值规划器，可经过已选关节路点；左侧规划保留原根系 X 的平移/进退顺序，中间 IK 只约束位置，终点 IK 才约束位置和朝向。
同一个 XYZ、不同朝向也可规划。目标完整位姿不可达会报错，不退化成仅 XYZ 的最近解。
开启碰撞检查时沿用碰撞/RRT 处理；RRT 路径的中途朝向也不受目标朝向约束。

执行后端独立选择，原方案和 50Hz 无需 PINK/锚定；选择 PINK 时沿用其锚定后取点的要求。
分段、横移、收回和其他关节动作沿用原设置，不因选择目标朝向而强制暂停或禁用。
执行前验证规划编号、路径、取点版本、TCP、记录内容和终点位姿，PINK 另核对世界锚点。
全程固定世界朝向、起点 2° 限制和途中朝向超限停止均已移除。
只在到位时核验末端目标位姿并报告终点朝向误差（验收容差 2°、位置 10 mm）；原方案仍是机器人基座系关节轨迹，PINK 则跟随随路径变化的世界系位姿参考。

验证：`tests/test_cabinet_orientation.py` 使用真实 H2 IK/PINK 模型和模拟执行器，覆盖起点与目标朝向相差 28.65°、同 XYZ 改朝向、不同执行后端和过期规划拒绝。
`tests/browser/cabinet_orientation.py` 拦截所有硬件写请求验证页面与原分段流程，未进行真机运动验收。

## 路点附带 RGBD 录制

18001 单臂页面和双臂工作台的“录制路点”使用一个页面内弹窗：先选“点位 + RGBD”或“仅录制点位”，再填写名称，点击“录制”提交；点击“取消”关闭，不保存。
默认选“点位 + RGBD”，使用 7005 `/api/pointcloud/recording-capture` 的默认拍摄参数（stride 4、0.15–3 m、服务默认置信度和模型）。不再使用浏览器 prompt/confirm；失败时在原弹窗显示原因并保留名称和选择，便于重试。
采集期间保持手臂和机身静止；18001 在读取拍摄前位姿后等待新的同帧 RGB/深度，随后读取拍摄后位姿。
这是软件静止快照，不是硬件时钟同步；前后两次原始位姿、采样时间、差异检查均保存在档案中。超过 1° 关节/朝向/躯干变化或 5 mm TCP 位移时报错，不提交路点。

路点 JSON 仍位于 `data/waypoints/<侧别-名字>_<时间戳>.json`，同名再次录制独立保存。
对应的 `<侧别-名字>_<时间戳>/rgbd/` 包含：

- `rgb.jpg`：原始彩色 JPEG；`depth_mm.npy`：对齐彩色图的完整 float32 深度，单位 mm、0 表示无效，不按点云距离范围裁剪。
- `robot_pose.json`：录制侧关节、躯干/IMU、TCP 定义与基座系位姿、相机/手部外参和标定来源、激活组合、前后采样与同步方式。
- `capture.json`：7005 默认参数、帧号、内参/畸变、检测结果和当时柜面算法配置；`cloud.bin`：同帧 PCV1 点云。
- `manifest.json`：路点文件名与上述资料的关联、尺寸、单位。

`POST /api/arms/<arm>/reach/waypoints/record_rgbd {"name":"A"}` 为明确的 RGBD 录制入口；原 `/waypoints` 也支持 `capture_rgbd: true`，默认 false。
失败不降级成仅关节录制；成功后路点列表显示“RGBD 已录制”。图片采集不会覆盖 7005 当前已冻结的选点帧，也不确认目标、不触发运动。
写入临时目录完成后才提交路点 JSON。删除列表中的路点时保留其 RGBD 原始档案，供恢复/离线分析。

此功能保存以后做柜面重定位所需的数据，不改变现有关节路点的回放语义。
后续柜面系 A/B 重定位必须使用柜上固定参考点作为原点：当前 7005 的 `origin_camera_m` 是相机原点在柜面的投影，会随站位移动，不能直接当成固定世界位置原点。
不从旧路点补造当时不存在的 RGBD；没有手眼标定的记录会保留 `calibration.ready: false`，不能直接用于柜面位姿换算。

验证：`tests/test_waypoint_rgbd.py`、`tests/test_rgbd_camera.py`、`tests/browser/waypoint_rgbd.py`，全程模拟、不发送机械臂控制命令。

## 补偿文件

可分别选择重力版本注册文件（如 `config/gravity_compensation.json`，另填版本）或负载辨识 JSON（`arm`、`mass_kg`、`com_m`、`alpha`）。
注册文件的组合兼容性必须匹配；负载文件的 arm 必须匹配。
负载辨识文件沿用辨识程序的 `alpha × 原模型重力 + 额外负载重力`：适配原控制器时使用 `payload_kg = mass_kg / alpha`。`with_hand: false` 剔除该侧原模型的 `hand_link` 及子树质量；`true` 或旧文件缺省时保留原模型手部质量。alpha 必须为正。
18000 每侧的“导入补偿 JSON”支持选择电脑文件或填写机器人服务器上的绝对路径。默认名称为完整 JSON 文件名（含扩展名），可在导入前修改。系统校验侧别和参数、自动分配版本号，将参数快照和来源写入 `config/gravity_compensation.json`，按当前手型号绑定；导入后在本侧下拉框选中新版本，再点“保存并激活”应用。相同来源、名称、参数和组合的重复导入复用已有记录，修改参数则保留旧版本并新增记录。
原“独立补偿文件”路径方式继续可用。“补偿版本库”列出已登记/导入的版本，不自动扫描外部目录。
已离线对照辨识模型验证两种格式的力矩一致性；不要仅凭文件名判断适用于当前换装手。

## 灵巧手服务

18089 新增 `/api/arms/left/{status,connect,command}` 和右侧对应接口，各侧连接独立。
原灵巧手页面及其视觉控制入口保留。相同设备且同一侧才可复用已有连接。
第二只串口手必须填写不同的独立串口，连接失败不会自动扫描到另一侧串口。第一版不支持两只 Modbus 手共用一条物理串口总线。
部署涉及 `eai-teleop-studio/hand_web` 和共享 `calib3d/arm.py`；更新后应重启 hand-web.service 和 reach_server。

## 接口和验证

`/api/arms/left_arm/reach/...` 与 `/api/arms/right_arm/reach/...` 对应原 reach 接口。
`18000 /api/capability/arms/{arm}` 保存期望配置；`18001 /api/dual/status` 只查看运行状态；`18001 /api/dual/reload-config/{arm}` 从 18000 重新加载某侧配置。旧的 `18001 /api/dual/config/{arm}` 不再接受写入。
原 `/api/reach/...` 始终对应启动默认侧；17001 的原 handcart 右手任务分发保持原行为。

